## Org extension #human #l

```l
l-prefix: date-timed-l-prefix | prioritized-l-prefix. L-names may be prefixed with `l-prefix`.

  date-timed-l-prefix: E.g. 20260126-143022-snapshot.md. Use for snapshots, logs, one-off captures where creation time matters. The `date '+%Y%m%d-%H%M%S'` may generate it.

  prioritized-l-prefix: ^\d{3}$, defining the priority of the task. Allows recognizing priority of the tasks just by listing files or directories. E.g. 002-my-chk.md or 003-my-task/. Use when org files or directories need ordering (tasks, checklists etc). The meaning of ranges for priorities:
    `000-099`: active work
    `100-899`: normal priority
    `900-999`: done (archive)

org-file: cell
  Org files are in org/ in any module.

  sections:
    todo: list of org-entry  ; ## Todo section with backlog ([ ]) and active ([>]) tasks, ordered by priority, top - highest
    done: list of org-entry  ; ## Done section with solved ([x]) tasks

org-entry: task | note
  May be nested.

  auto-discovery: child org-files and org-directories inside a parent's scope automatically belong to that parent's `## Todo`. Membership is by filesystem presence; order by L-prefix. Parents do not list children explicitly.

  storage: inline | org-file | org-directory
    inline: in the current file. For tasks priority is defined by the position in the file, where higher position in the file means higher priority.
      Parent scope: parent org-entry.
    org-file: in the separate file when the org-entry is large enough.
      Parent scope: index.md in the current directory, if missing then the parent's directory index.md (recursively if missing).
    org-directory: when there must be >= 2 files. Must have the index.md task file and >= 0 other files and directories.
      Parent scope: parent index.md, if missing then the parent's directory index.md (recursively if missing).
      phase: an org-directory whose name uses L-prefix to order a sequence (e.g. `010-resources/`, `020-cluster/`). The parent references the directory; status marker stays on the parent reference.

    When stored either as org-file or org-directory the L-prefix (NNN-, see below) defines the priority.

  task: cell
    status: pending | active | done
      pending: `[ ]`
      active: `[>]`
      done: `[x]`
      cancelled: `~[x]~`
    tags:
      due: date-time?   ; #due:YYYY-MM-DD or #due:N-unit (e.g. #due:1-day)
      start: date-time? ; #start:YYYY-MM-DD or #start:N-unit
      cost: ?           ; Expected effort, unit currently unknown (to be fixed when the cost model is decided)
      size: cost        ; size is an alias of cost - the "task / quest / epic" tiers come from cost ranges

  note: cell
    Non-actionable textual content. Used to capture context, raw descriptions, examples, or any typical markdown prose that is NOT a task specification.

    When in a task's scope (inline under a task or inside the task's org-file / org-directory), the note relates to that task and reads as additional task details - context, raw descriptions, examples, observations.

    format: markdown ; any valid markdown block - list item (`- ` or `* `) or plain prose
    storage: inline | org-file | org-directory  ; same options as task

    Properties:
      No status (notes are not actionable)
      No due, start, cost (no schedule or budget)
      Tags are allowed

task-list: list of task
  size: int ; The length of the list

org-graph: graph (subgraph) of tasks or notes. May be subgraph, i.e. org-graphs may be nested. E.g. the org-graph of active tasks means the all org tasks, marked with `[>]`.

check-list (checklist): list of check
  check (test): GWTB predicate
    format: "Given <context>, when <trigger>, then <expected>, because <reason>". The `gwtb` abbreviates this format.
    context: when to run
    trigger: action or event
    expected: required outcome (from "then" clause)
    reason: justification (documentation, not evaluated)
    Evaluation: run the action, compare expected result with the real one, it must be one of:
      PASS: evidence exactly matches expected
      FAIL: any deviation or "but" in evidence

gate: predicate, working as assertion. May call the /goal skill. May be implemented as ANDed steps and may contain child gates.

contract: cell
  Attachable composite assertion - the Meyer sandwich: (inv && pre) -> body? -> (post && inv). Can be attached to any entity (flow, step, module, etc) and starts act on its respective scope.

  pre: gate    ; Checked at first step
  post: gate   ; Checked at last step.
  inv: gate    ; Checked before `pre` and after `post`.

scope: context for its content. Works like static (lexical) scope in programming languages. May have additional semantics (rules) attached (e.g. with tags or different way) which will work for this scope only.

flow-contract #contract
  A contract attached to a flow boundary. Extends contract, adding visibility.
  pre: gate
    Assertions on input, checked at first step
  post: gate
    Assertions on output, checked at last step
  inv: gate
    Assertions for both input and output, checked against input at first step (before `pre`) and against output at last step (after `post`).

  visibility: public | private
    public: scope which is exposed to the caller. Can reference content from the own scope and parent public scopes. Can't reference contents from private scope.
    private: scope which is hidden from the caller. Can reference content from the own scope and parent scopes which may be public or private scopes.

public-flow-contract: #flow-contract
  visibility: public ; Everything in this scope is visible to caller. 

private-flow-contract: #flow-contract
  visibility: private ; Everything in this scope is hidden from caller. 

flow: cell
  Executable unit. Black box to the caller, exposing only its public-flow-contract. Implemented as the agent's `/` commands. The agent runs flows by executing steps as instructions. Not all `/` commands may be flows - only those which follow the flow format. See /check:flow for the template and checks.

  Evaluation rules: run four gates and body, fail loudly, in order:
    public(inv && pre) -> private(inv && pre) -> body -> private(post && inv) -> public(post && inv)

  context: (check, prose: text?)
    Minimal documentation for the caller: at least one GWTB check, then optional prose. Interface-level only; exposes no internals.

  public:
    public-flow-contract ; Attached and brings additional semantics to this scope.
      Has no body - `public:` is shape only, does not have actionable steps.

      ; Signature: my-arg-1 -> my-arg-2 ... -> my-return.
      input: any    ; The value the flow receives; the public-flow-contract's pre constrains it - inv and pre.
      output: any   ; The value the flow returns; the public-flow-contract's post constrains it - post and inv.

  private:
    private-flow-contract ; Attached and brings additional semantics to this scope.

  body: steps?
    steps: list of step, loop (>= 1). Concrete algorithm transforming input to output. Runs in private context and is never exposed to the caller.

lens: cell
  Mental tool that reveals specific view of target (zoom-out: system view, zoom-in: internal view). Inspired by Jesse Schell's "The Art of Game Design"

org-flow: list of flow
  The canonical sequence of flows every task passes through, from intent capture to closure.
  chain: /capture -> /orient -> /analyze -> /solve -> /integrate -> /observe -> /done
```

### Flow definition in Lean

```lean
inductive Error where
  | publicEntry
  | privateEntry
  | privateExit
  | publicExit
  | other (message : String)
  deriving Repr, DecidableEq

inductive Visibility where
  | pub
  | priv
  deriving Repr, DecidableEq

/-- A contract: the Meyer triple ⟨pre, post, inv⟩ over a subject state `σ`.
`pre` constrains the entry, `post` the exit, `inv` both. No visibility of its own. -/
structure Contract (σ : Type) where
  pre  : σ → Bool
  post : σ → Bool
  inv  : σ → Bool

/-- A flow-contract extends a contract with visibility: `pub` = the exported boundary (caller-facing), `priv` = the internal representation (hidden). -/
structure FlowContract (σ : Type) extends Contract σ where
  visibility : Visibility

/-- A `Flow` bundles a public flow-contract and a private flow-contract around the `body`.
The public contract is checked over the exported interface, the private over the representation; here both share `σ` for brevity. -/
structure Flow (σ : Type) (m : Type → Type) where
  pub  : FlowContract σ
  priv : FlowContract σ
  body : m Unit

@[inline] def gate [Monad m] [MonadExcept Error m]
    (predicate : Bool) (kind : Error) : m Unit :=
  if predicate then pure () else throw kind

/-- Four gates, fail loudly, in order:
`public(inv && pre) -> private(inv && pre) -> body -> private(post && inv) -> public(post && inv)`. -/
def Flow.run
    [Monad m] [MonadStateOf σ m] [MonadExcept Error m]
    (flow : Flow σ m) : m Unit := do
  let s₀ ← get
  gate (flow.pub.inv s₀ && flow.pub.pre s₀) .publicEntry
  gate (flow.priv.inv s₀ && flow.priv.pre s₀) .privateEntry
  flow.body
  let s₁ ← get
  gate (flow.priv.post s₁ && flow.priv.inv s₁) .privateExit
  gate (flow.pub.post s₁ && flow.pub.inv s₁) .publicExit
```
